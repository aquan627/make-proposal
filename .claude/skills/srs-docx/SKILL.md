# 요구사항명세서(.docx) 작성

회사 템플릿은 대외 산출물 양식이므로 **저장소에 커밋하지 않는다**. 사용자에게 첨부를 요청한다.

## 절차

1. 템플릿 구조 파악: `unzip`으로 풀어 `word/document.xml`의 표지 표, 문서정보 표, 개정이력 표, 목차(TOC 필드), 제목 스타일 ID(제목1·제목2), 본문 표 서식, `header1.xml`/`footer1.xml`을 확인한다.
2. 내용 원본은 `docs/REQUIREMENTS.md`다. 장(##)은 제목1, 절(###)은 제목2, 표는 템플릿 표 서식(회색 머리행, 머리행 반복), 글머리표는 템플릿의 글머리 번호를 쓴다.
3. 템플릿의 안내 문구(파란 기울임 "~기술한다")는 지우고 실제 내용으로 채운다.
4. 바꿀 값: 표지 프로젝트명·문서명, 문서ID·버전·작성일·작성자, 개정이력 첫 행, 머리글(프로젝트명·수행사·수행기간·담당자).
5. **템플릿의 원래 고객사 로고·이름은 제거**한다(다른 프로젝트 정보가 남지 않게). 회사 로고는 유지.
6. 목차: 제목마다 북마크를 달고, PDF로 렌더링해 실제 쪽 번호를 찾아 목차에 넣는다(2회 빌드).
7. 검증: docx 스킬의 `validate.py`, LibreOffice로 PDF 렌더링 후 표지·목차·본문 표를 눈으로 확인.
8. 파일명은 `요구사항명세서.docx`. 임의로 정한 값(문서ID 등)은 사용자에게 확인 요청 목록으로 알린다.
