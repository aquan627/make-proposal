# 배포 장애 대응

## 먼저 볼 것

1. 사용자가 본 **오류 문구 원문**과 접속 주소를 받는다.
2. Vercel 최신 배포 상태(READY/ERROR)와 커밋.
3. 환경변수의 **이름과 적용 환경**(값은 보지 않는다).
4. 최근 1시간 런타임 로그.

## 증상별 원인과 조치

| 화면 문구 / 증상 | 원인 | 조치 |
| --- | --- | --- |
| "관리자가 Vercel 환경변수 APP_PASSWORD(8자 이상)를 설정해야…" | APP_PASSWORD 없음, 8자 미만, 또는 **Development에만 체크** | Production에 체크(값 유지) 후 재배포 |
| "GEMINI_API_KEY 환경변수가 설정되지 않았습니다" | 키 없음, 이름 오타, **Development에만 체크**, 또는 키 값을 이름 칸에 입력 | 이름 `GEMINI_API_KEY`, Production 체크 후 재배포 |
| "Gemini API 키가 올바르지 않습니다" | 키 값 오타·폐기된 키 | AI Studio에서 키 재발급 후 값 교체, 재배포 |
| "Gemini 사용 한도를 넘었습니다" | 무료 등급 분당·일일 한도 (분석 1회 = 호출 2회) | 1~2분 대기 |
| "Failed to fetch" / "처리 도중 연결이 끊겼습니다" | 긴 요청이 중간에 끊김(회사망 프록시 등) | 스트리밍 연결 유지가 적용된 최신 배포인지 확인, 새로고침, 짧은 RFP로 재시도 |
| "처리 시간이 초과됐습니다" (504) | 300초 초과 | RFP 분량 축소, 요구사항 부분만 입력 |
| "로그인이 필요합니다" | 세션 만료(12시간) 또는 APP_PASSWORD 변경 | 다시 로그인 |
| "허용되지 않은 출처의 요청입니다" | 다른 도메인에서 API 호출 | 같은 주소에서 사용 |
| 빌드 ERROR | 타입 오류·의존성 | 빌드 로그 확인, 로컬 `npm run check`로 재현 |
| 예전 화면이 보임 | 브라우저 캐시, 다른 배포 주소 접속 | 새로고침, Production 주소 사용 |
